# k8s远程开发环境

问题背景是，我有多个设备可以进行开发工作，但是每个设备的环境并不一致，导致开发体验割裂。

我做了一个尝试：使用 chezmoi 进行 config 同步，后来尝试用chezmoi执行脚本来统一工具环境，比如git、typescript 等等，后来发现这样由 chezmoi apply 触发的工具同步有几个问题：

1. 系统包管理器需要 sudo，我们没办法割舍系统包管理器，因为有部分软件比如vim、htop他是没有npm、pipy的包管理器安装方式的，也没有二进制方式，只有古老的动态链接，如果我们要解决这个问题，本质上需要自己构建一个软件包平台，可见 chezmoi 只适合 config 同步，软件的安装实际上并不是一个简单的问题，不是 "在 chezmoi 同步的时候顺手执行一个小脚本" 这样的简单问题

2. 即使 tool 同步了，状态也不同步，tool 同步其实不是带来麻烦的根本问题，因为 tool 只需要安装一次大部分时候就不用动了，但是状态更新是随机发生的，比如 codex 的会话，GitHub cli 的登录状态等

所以我们可以总结出：tools（运行时安装的工具），config，secret，state 等数据是需要分开处理的开发环境信息。当我对开发环境进行进一步抽象的时候，我注意到 k8s 其实早就帮我把这些资源抽象好了:

1. role: 谁可以访问开发环境
2. image: 开发环境用什么发行版，有哪些工具
3. config: 容器内开发工具使用的 config
4. secret: 容器内开发工具使用的 secret
5. pvc: 开发环境的临时文件系统

k8s 本意是为生产环境设计的，然而生产环境所需的资源在开发环境同样需要，所以我们可以沿用同一套资源抽象。

我的思路是，先手动使用 k8s 作为开发环境，只有面临真实问题的时候，才需要把这个 workflow 开发成一个独立产品。
